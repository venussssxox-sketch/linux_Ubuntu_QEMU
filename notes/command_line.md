  ## 1. 当前目录与目录切换

  ### 知识点

  Linux 目录是树状结构。`~` 表示当前用户的家目录，`..` 表示上一级目录。

  ### 我执行的命令

  ```bash
  cd ~
  cd ~/Downloads
  cd ttest
  cd ../
  cd zhaojinxin

  ### 命令作用

  - cd ~：回到当前用户的家目录，例如 /home/zhaojinxin。
  - cd ~/Downloads：进入家目录下的 Downloads 文件夹。
  - cd ttest：进入当前目录下的 ttest。
  - cd ../：进入上一级目录。
  - cd zhaojinxin：尝试进入当前目录下名为 zhaojinxin 的子目录。

  ### 我观察到的现象

  - 你先进入家目录，再创建并进入 ttest，说明相对路径和绝对路径都进行了练习。
  - 输入过 ce ttest，这是错误命令；正确命令是 cd ttest。
  - 从家目录执行 cd zhaojinxin 时，大概率会失败，因为它会寻找 /home/zhaojinxin/
    zhaojinxin，而不是家目录本身。

  ### 我应该掌握的结论

  - cd ~ 与 cd /home/zhaojinxin 都能进入家目录。
  - 相对路径依赖当前所在位置；绝对路径从 / 开始，不依赖当前目录。
  - 路径中不要漏写 /，也不要把命令拼错。

  ### 仍需补充的知识

  pwd
  cd -
  cd /tmp
  cd ..

  理解 .、..、~、/ 和 - 分别代表什么。

  ## 2. 查看当前位置和文件列表

  ### 知识点

  查看目录内容是文件管理的基础。ls 用于列出文件，pwd 用于显示当前工作目录。

  ### 我执行的命令

  pwd
  ls
  ls test1/

  ### 命令作用

  - pwd：输出当前工作目录的完整路径。
  - ls：列出当前目录的内容。
  - ls test1/：列出 test1 目录中的内容。

  ### 我观察到的现象

  - 你多次在创建、复制、移动、删除后执行 ls，这是正确的验证习惯。
  - ls test1/ 用于确认文件 a..c 是否被移动到 test1 中。

  ### 我应该掌握的结论

  每次会修改文件系统的操作后，都应使用 ls 或 find 验证结果。

  ### 仍需补充的知识

  ls -l
  ls -la
  ls -lh
  ls -R

  重点理解权限、文件大小、隐藏文件和递归列出的含义。

  ## 3. 创建文件、复制、移动与重命名

  ### 知识点

  Linux 中文件名只是一个名称；.c、.txt 等扩展名本身不决定文件真实类型。touch 可
  创建空文件，cp 复制文件，mv 可移动或重命名。

  ### 我执行的命令

  touch a.c
  cp a.c b.c
  mv a.c b.c
  touch a..c
  mv a..c test1

  ### 命令作用

   命令             作用
  ━━━━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   touch a.c        创建空文件 a.c；若文件存在则更新访问和修改时间。
  ───────────────  ────────────────────────────────────────────────────
   cp a.c b.c       将 a.c 复制为 b.c。
  ───────────────  ────────────────────────────────────────────────────
   mv a.c b.c       将 a.c 重命名为 b.c。
  ───────────────  ────────────────────────────────────────────────────
   touch a..c       创建名为 a..c 的空文件。
  ───────────────  ────────────────────────────────────────────────────
   mv a..c test1    因为 test1 是目录，所以将 a..c 移动到 test1/a..c。

  ### 我观察到的现象

  - cp a.c b.c 后，目录中应同时存在 a.c 和 b.c。
  - mv a.c b.c 后，a.c 不再存在，文件名变为 b.c。
  - mv a..c test1 后，配合后续 ls test1/，说明你在验证“移动到目录”这一行为。
  - 文件名 a..c 是合法的；Linux 不禁止文件名中出现连续两个点。

  ### 我应该掌握的结论

  - cp 会保留源文件，mv 不会。
  - mv 源文件 新文件名 是重命名。
  - mv 源文件 目录名 是移动。
  - Linux 区分大小写，A.c 与 a.c 是不同文件。

  ### 仍需补充的知识

  cp -i a.c b.c
  mv -i a.c b.c
  cp -r dir1 dir2

  -i 会在覆盖前询问；复制目录通常需要 -r。

  ## 4. 创建、重命名与删除目录

  ### 知识点

  目录用于组织文件。删除操作具有风险，特别是 rm -rf。

  ### 我执行的命令

  mkdir ttest
  mkdir test
  mkdir 1
  mkdir test1
  mv test test1
  rmdir 1
  rm ttest/ -rf
  rm test1/ -rf

  ### 命令作用

   命令              作用
  ━━━━━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   mkdir <目录名>    创建目录。
  ────────────────  ──────────────────────────────────
   mv test test1     将目录 test 重命名为 test1。
  ────────────────  ──────────────────────────────────
   rmdir 1           删除空目录 1。
  ────────────────  ──────────────────────────────────
   rm -rf <目录>     强制递归删除目录及其中全部内容。

  ### 我观察到的现象

  - 你创建了空目录 1 后使用 rmdir 1 删除，符合 rmdir 只能删除空目录的使用场景。
  - 你先创建 test，再用 mv test test1 完成目录重命名。
  - 在 ttest 目录内执行 rm ttest/ -rf 时，目标会被理解为当前目录中的 ttest/ 子目
    录，大概率提示“没有那个文件或目录”；之后回到上一级执行相同命令，才删除了真正
    的 ttest。

  - 最后执行 rm test1/ -rf，删除了其中的文件和目录。

  ### 我应该掌握的结论

  - rmdir 只能删除空目录。
  - rm -r 能递归删除目录，-f 表示不询问、忽略多数错误。
  - rm -rf 很危险，执行前必须确认当前位置和目标路径。
  - 建议把选项放在目标前面：

  rm -rf test1/

  不要写成：

  rm test1/ -rf

  ### 仍需补充的知识

  rm -i file
  rm -rI directory
  trash-put file

  重点理解交互删除、批量删除确认，以及桌面环境回收站工具。

  ## 5. 查看网络接口与安装网络工具

  ### 知识点

  网络接口、IP 地址、路由表和邻居表共同决定主机能否通信。ifconfig 是传统工具，ip
  是现代 Linux 的推荐工具。

  ### 我执行的命令

  if config
  ifconfig
  sudo apt install net-tools
  ifconfig
  ifconfig -a
  ip addr
  ip link
  ip route
  ip neigh

  ### 命令作用

   命令                          作用
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   if config                     错误写法；正确命令是连续的 ifconfig。
  ────────────────────────────  ────────────────────────────────────────────────
   ifconfig                      查看活动网络接口的地址、MAC 地址和流量统计。
  ────────────────────────────  ────────────────────────────────────────────────
   sudo apt install net-tools    安装提供 ifconfig 的 net-tools 软件包。
  ────────────────────────────  ────────────────────────────────────────────────
   ifconfig -a                   查看全部网络接口，包括已关闭的接口。
  ────────────────────────────  ────────────────────────────────────────────────
   ip addr                       查看接口及 IPv4、IPv6 地址。
  ────────────────────────────  ────────────────────────────────────────────────
   ip link                       查看网卡名称、MAC 地址和 UP/DOWN 状态。
  ────────────────────────────  ────────────────────────────────────────────────
   ip route                      查看路由表和默认网关。
  ────────────────────────────  ────────────────────────────────────────────────
   ip neigh                      查看邻居表；IPv4 中主要是 ARP 的 IP 到 MAC 映
                                 射。

  ### 我观察到的现象

  - 先运行 ifconfig，随后安装 net-tools，说明系统最初未安装该传统工具或该命令不
    可用。

  - 安装后继续使用 ifconfig 和 ifconfig -a，说明你成功开始查看网卡信息。
  - 随后使用 ip addr、ip link、ip route、ip neigh，完整检查了地址、链路、路由和
    ARP 邻居信息。

  - 历史记录没有保存实际输出，因此无法还原当时的 IP、MAC、默认网关和邻居条目。

  ### 我应该掌握的结论

  - 新系统中优先使用 ip，不应依赖 ifconfig。
  - ip addr 看 IP 地址。
  - ip link 看网卡是否为 UP 或 DOWN。
  - ip route 中的 default via <网关IP> 表示默认网关。
  - ip neigh 能帮助判断网关或局域网主机的 ARP 解析状态。

  ### 仍需补充的知识

  ip -br addr
  ip route get 1.1.1.1
  nmcli device status
  resolvectl status

  理解 CIDR 前缀长度、默认路由、DHCP、ARP 和 DNS。

  ## 6. 启用和停用网络接口

  ### 知识点

  网卡可被设置为启用或停用。停用网络接口会导致该接口无法收发数据。

  ### 我执行的命令

  sudo ifconfig enp108s0
  sudo ifconfig enp108s0 down
  ifconfig
  sudo ifconfig enp108s0 up
  ifconfig

  ### 命令作用

  - sudo ifconfig enp108s0：查看指定接口 enp108s0 的信息。
  - sudo ifconfig enp108s0 down：停用该网卡。
  - sudo ifconfig enp108s0 up：重新启用该网卡。
  - 两次 ifconfig：分别验证停用和恢复后的状态。

  ### 我观察到的现象

  - 你对 enp108s0 完成了“查看 → 停用 → 验证 → 恢复 → 验证”的完整练习。
  - 操作使用 sudo，说明改变网络接口状态需要管理员权限。
  - 历史记录不包含输出，无法确认停用期间的接口显示和恢复后的地址状态。

  ### 我应该掌握的结论

  - down 使接口停止工作，up 重新启用接口。
  - 更推荐的现代写法是：

  sudo ip link set dev enp108s0 down
  sudo ip link set dev enp108s0 up

  - 远程 SSH 登录时不要对正在使用的网络接口执行 down，否则会断开连接。

  ### 仍需补充的知识

  - 管理状态与物理链路状态的区别。
  - DHCP 租约如何获取和续租。
  - NetworkManager 的 nmcli 命令。

  ## 7. 查看帮助和手册

  ### 知识点

  不熟悉命令时，应先查帮助或手册，再执行可能有副作用的操作。

  ### 我执行的命令

  ifconfig -h
  rm -h
  mkdir -h
  rm --h
  man printf

  ### 命令作用

  - ifconfig -h：尝试查看 ifconfig 的帮助。
  - rm -h：尝试查看 rm 的帮助或使用 -h 参数。
  - mkdir -h：查看 mkdir 的帮助。
  - rm --h：错误或不完整的长选项写法。
  - man printf：查看 printf 的完整手册。

  ### 我观察到的现象

  - 你尝试了短选项和长选项的帮助写法。
  - rm --h 通常会被识别为无效选项；长选项通常应写成完整形式，例如 --help。
  - man printf 会进入分页阅读界面，通常按 q 退出。

  ### 我应该掌握的结论

  优先使用：

  命令 --help
  man 命令

  例如：

  rm --help
  mkdir --help
  man rm
  man mkdir

  ### 仍需补充的知识

  - 在 man 中按 /关键字 搜索。
  - 按 n 跳到下一处搜索结果。
  - 按 q 退出。

  ## 8. 查找文件与搜索文本

  ### 知识点

  find 按文件属性查找，grep 在文件内容中搜索文本。

  ### 我执行的命令

  find a..c
  find -name a.c
  find -name a..c
  grep -nr "Ubuntu" /

  ### 命令作用

   命令                   作用
  ━━━━━━━━━━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   find a..c              将 a..c 当作起始路径查找；若该路径不存在则报错。
  ─────────────────────  ──────────────────────────────────────────────────
   find -name a.c         从当前目录递归查找名称为 a.c 的文件。
  ─────────────────────  ──────────────────────────────────────────────────
   find -name a..c        从当前目录递归查找名称为 a..c 的文件。
  ─────────────────────  ──────────────────────────────────────────────────
   grep -nr "Ubuntu" /    从根目录递归搜索包含 Ubuntu 的内容，并显示行号。

  ### 我观察到的现象

  - a..c 已被移动到 test1/，因此直接执行 find a..c 很可能因当前目录下不存在该路
    径而报错。

  - find -name a..c 可以递归定位到类似 ./test1/a..c 的结果。
  - grep -nr "Ubuntu" / 搜索范围是整个根目录，会访问大量系统文件，通常产生大量结
    果、权限不足提示或二进制文件提示。

  ### 我应该掌握的结论

  - find 的常用写法是：

  find <起始目录> -name "<文件名>"

  例如：

  find . -name "a..c"
  find ~ -type f -name "*.c"

  - 不要轻易对 / 执行递归 grep；范围过大、速度慢，也会遇到权限问题。
  - 搜索文本时优先指定项目目录或家目录。

  ### 仍需补充的知识

  grep -RIn "Ubuntu" ~/linux_Ubuntu
  find . -type f -name "*.md"
  rg -n "Ubuntu" .

  其中 rg（ripgrep）通常比递归 grep 更快、更适合代码目录。

  ## 9. 查看磁盘与目录空间

  ### 知识点

  du 用于统计目录占用空间，df 用于查看文件系统整体空间。

  ### 我执行的命令

  du
  du test1/-sh
  du test1/ -sh
  df

  ### 命令作用

   命令             作用
  ━━━━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   du               递归显示当前目录下各文件和目录的磁盘占用。
  ───────────────  ────────────────────────────────────────────────────
   du test1/-sh     将 test1/-sh 当作路径，通常会因路径不存在而报错。
  ───────────────  ────────────────────────────────────────────────────
   du test1/ -sh    显示 test1/ 的总大小；-s 为汇总，-h 为易读单位。
  ───────────────  ────────────────────────────────────────────────────
   df               显示各已挂载文件系统的总容量、已用空间和可用空间。

  ### 我观察到的现象

  - 你先执行完整的 du，再改用 -s -h 查看目录汇总大小，体现了从详细信息到简洁统计
    的过程。

  - du test1/-sh 把选项误写进了路径；正确写法应将选项与路径分开。
  - df 输出的重点是根文件系统 / 的可用空间和使用率。

  ### 我应该掌握的结论

  - du 回答“某个目录占多少空间”。
  - df 回答“某个文件系统还剩多少空间”。
  - 常用命令：

  du -sh .
  du -sh ~/*
  df -h

  ### 仍需补充的知识

  - inode 用尽和磁盘空间用尽的区别：

  df -i

  - 使用 sort -h 找出大目录：

  du -sh ~/* 2>/dev/null | sort -h

  ## 10. 文本文件、查看内容与识别类型

  ### 知识点

  cat 输出文件内容，file 根据文件内部特征识别实际类型，不只看扩展名。

  ### 我执行的命令

  gedit a,c
  cat a.c
  cat a,c
  file a,c
  file test1/a..c

  ### 命令作用

  - gedit a,c：用图形编辑器打开或创建名为 a,c 的文件。
  - cat a.c：输出 a.c 内容。
  - cat a,c：输出 a,c 内容。
  - file a,c：识别 a,c 的实际文件类型。
  - file test1/a..c：识别移动后的 a..c 文件类型。

  ### 我观察到的现象

  - 你创建过 a.c，但编辑器命令使用的是 a,c，逗号和点不同，因此这是两个不同文件。
  - 若 touch 创建的文件没有写入内容，cat 通常没有输出，file 通常会显示 empty。
  - file 可以验证扩展名为 .c 的文件不一定是 C 源代码；空文件仍只是空文件。

  ### 我应该掌握的结论

  - Linux 文件名中的 . 与 , 完全不同。
  - cat 适合查看短文本文件。
  - file 判断的是内容特征，扩展名只是命名习惯。

  ### 仍需补充的知识

  less 文件名
  head 文件名
  tail 文件名
  nano 文件名

  了解如何高效查看大文件和在终端编辑文本。

  ## 11. 查看进程与实时系统监控

  ### 知识点

  进程是正在运行的程序实例。ps 查看某一时刻的进程快照，top 提供实时刷新视图。

  ### 我执行的命令

  ps
  ps -a
  ps -aux
  top

  ### 命令作用

   命令       作用
  ━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   ps         显示当前终端中属于当前用户的进程。
  ─────────  ──────────────────────────────────────────────────────────
   ps -a      显示带终端的其他进程。
  ─────────  ──────────────────────────────────────────────────────────
   ps -aux    显示系统中较完整的进程信息，包括 CPU、内存、PID 和命令。
  ─────────  ──────────────────────────────────────────────────────────
   top        实时显示进程、CPU、内存和负载信息。

  ### 我观察到的现象

  - ps、ps -a、ps -aux 逐步扩大了查看范围。
  - top 是交互式程序；历史记录后续还有命令，说明你已从 top 中退出，通常使用 q。

  ### 我应该掌握的结论

  - PID 是进程 ID，可用于定位或结束进程。
  - ps aux 中重点关注 %CPU、%MEM、STAT、COMMAND。
  - top 中按 q 退出，按 P 可按 CPU 使用率排序，按 M 可按内存排序。

  ### 仍需补充的知识

  ps -ef
  pgrep -a <进程名>
  kill <PID>
  kill -9 <PID>
  htop

  重点理解正常结束进程与强制结束进程的区别。

  ## 12. 删除文件与查看历史命令

  ### 知识点

  删除文件需确认目标；Shell 历史可以导出为学习记录。

  ### 我执行的命令

  rm a,c
  rm a.c
  history > ~/terminal_history.txt

  ### 命令作用

  - rm a,c：删除名为 a,c 的文件。
  - rm a.c：删除名为 a.c 的文件。
  - history > ~/terminal_history.txt：将当前 Shell 的历史命令输出并覆盖写入 ~/
    terminal_history.txt。

  ### 我观察到的现象

  - 你先通过 cat 和 file 查看文件，再删除，操作顺序合理。
  - 最后一条命令成功生成了本次分析所使用的 terminal_history.txt。
  - > 是覆盖重定向；重复执行会覆盖旧记录。

  ### 我应该掌握的结论

  - 删除前先使用 ls、file 或 pwd 确认目标。
  - 若想保留旧历史并追加内容，应使用 >>：

  history >> ~/terminal_history.txt

  - 但重复追加会产生重复记录；学习笔记更适合人工整理后提交到 Git。

  ### 仍需补充的知识

  history
  history | tail -n 20
  !123

  了解如何查看最近命令，以及如何按历史编号重新执行命令。
